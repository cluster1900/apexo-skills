# 中国招标文件合规预审技能 (`cn-tender-review` v0.1.0)

> **免责声明（每次输出报告头部必须完整保留）**
> 本技能基于公开法规条文与常见实务检查清单提供辅助性预审，可能存在误报、漏报与地区性特殊规定未覆盖的情况。输出不构成法律意见或招标执业意见。发标、投诉、应标等正式行为请咨询具备资质的专业人员，并以现行有效法律、规章、标准招标文件及项目主管机关要求为准。

> **数据与隐私提示**
> 本技能默认仅在本机读取与解析用户提供的招标文件，不包含任何外部上传逻辑或密钥。若当前会话连接的是云端大模型提供商（如 Grok、Gemini、OpenAI、Anthropic 等），文件抽取的文本片段将随模型请求发送至所选模型服务商；涉密或未公开敏感标书请确认合规后再提交。

## 1. 适用场景与输入处理

### 支持的输入格式
- **优先支持**：`PDF`（含可提取文本层）、`DOCX`、`TXT`、`MD`
- **转换支持**：`DOC`（可通过本机只读工具转换为文本后审查）
- **多文档对照**：支持「招标文件正文 + 补遗/澄清/答疑文件」联合审查（见规则 `CONSIST-ADDENDUM`）

### 扫描件 / 无文本层 PDF 强制降级路径（`SCAN-NO-TEXT-LAYER`）
当读取 PDF 后发现以下任一情形时：
1. 提取出的有效汉字字符数极少（例如每页平均少于 20 个有效字符，或全文仅含页眉水印/图片对象）；
2. 页面主要由嵌入图像（Scanned Image）构成且无 OCR 文本层；

**必须立即执行降级，严禁假装已完成实质条款审查**：
- 输出严重级别为 `blocker` 的发现项 `SCAN-NO-TEXT-LAYER`（标题：`扫描版或无文本层 PDF 无法直接提取条款文本`）；
- 明确告知用户无法定位具体条款，建议先执行本地 OCR（如 `ocrmypdf` / 扫描件文字识别）或提供可编辑的 `DOCX` 原稿后再重新运行审核。

## 2. 交互与审查五步流程

### 第一步：识别项目类型与适用法律域
在开始规则判定前，必须先从招标公告、投标人须知前附表、资金来源及采购方式中判定项目所属法域：

| 项目类型 | 核心适用法规 | 关键特征 |
| --- | --- | --- |
| **类型 I：依法必须进行招标的工程建设项目**（住建/交通/水利/能源等工程总承包、施工、监理、与工程建设有关的重要设备材料） | 《中华人民共和国招标投标法》《中华人民共和国招标投标法实施条例》 | 提述"依法必须进行招标"、工程量清单、最高投标限价（招标控制价）、资质等级 |
| **类型 II：政府采购货物和服务招标项目**（财政性资金，纳入集中采购目录或达限额标准的货物/服务） | 《中华人民共和国政府采购法》《中华人民共和国政府采购法实施条例》《政府采购货物和服务招标投标管理办法》（财政部令第 87 号） | 提述"政府采购"、采购预算、财政资金、落实中小企业/节能环保政府采购政策 |
| **类型 III：企业自主招标 / 非依法必须招标项目** | 当事人约定及本单位采购管理制度；若招标文件明确声明参照《招标投标法》或 87 号令执行，则按其声明核对 | 非财政资金且不属于法定必须招标范围的商业采购 |

- **类型不明时的处理**：若文档未指明项目类型，必须在报告头部显式标注所采用的**假设基准**，将受法域差异影响的规则结论 `confidence` 降级为 `medium` 或 `low`，并在报告末尾向用户提问确认。

### 第二步：抽取核心元数据与时间表
从招标文件中结构化提取并交叉核对以下字段（同时检查正文与前附表是否一致）：
1. 项目名称、招标人/采购人、招标代理机构；
2. 预算金额 / 最高投标限价（招标控制价，注意核对大小写金额）；
3. **关键时间节点**：
   - 招标公告发布之日 $T_{\text{announce}}$
   - 招标文件/资格预审文件开始发出（提供）之日 $T_{\text{sale\_start}}$ 与停止发售（提供）之日 $T_{\text{sale\_end}}$
   - 资格预审申请文件提交截止之日 $T_{\text{pq\_deadline}}$
   - 踏勘现场 / 投标预备会 / 提问截止 / 澄清修改发出之日 $T_{\text{clarify}}$
   - 投标文件提交截止之日 $T_{\text{bid\_deadline}}$ 与开标时间 $T_{\text{open}}$
4. 投标保证金金额、比例、提交形式、退还条件与投标有效期；
5. 资格条件（资质、业绩、财务、信誉、联合体、进口产品授权等）；
6. 评标方法（综合评估法/综合评分法 vs 经评审的最低投标价法/最低评标价法）、各分项权重、价格分计算公式与总分；
7. 否决投标/无效投标条款清单及合同专用条款核心风险点。

### 第三步：按规则库逐项核查（A ~ F 六大类）
详细判据与法条原文摘录见 [`references/checklist-rules.md`](references/checklist-rules.md) 与 [`references/laws-and-regulations.md`](references/laws-and-regulations.md)。

| `TIME-PQ-5D` | 依法必须招标项目 | 提交资格预审申请文件的时间，自资格预审文件停止发售之日起**不得少于 5 日** | 《招标投标法实施条例》第 17 条 | `blocker` |
| `TIME-CLARIFY-15D` | 依法必须招标项目 / 政府采购公开招标 | 澄清或修改可能影响投标文件编制的，应在投标截止时间**至少 15 日前**书面通知；不足 15 日的，应当顺延提交投标文件的截止时间 | 《招标投标法》第 23 条、《实施条例》第 21 条；财政部令第 87 号第 27 条 | `high` |

## 3. 输出报告格式规范（Markdown + JSON）

每次审核必须输出包含以下两部分的报告（完整模板见 [`references/report-template.md`](references/report-template.md)）：

1. **人类可读的 Markdown 报告**：
   - **报告头部**：技能名称与版本（`cn-tender-review v0.1.0`，`ruleset_version: 2026-10-28`）、分析时间、源文件名与 SHA256（若可读本地文件）、项目类型判定及假设、**完整免责声明**；
   - **统计汇总表**：按 `blocker` / `high` / `medium` / `low` / `info` 统计发现项数量；
   - **关键时间线与金额核验表**：列出抽取的日期、计算出的自然日/工作日間隔、预算与保证金占比；
   - **逐条发现详情（按严重级别排序）**：每条必须包含 `id`、`severity`、`title`、`category`、`location`（页码/章节/条款号）、`evidence`（原文摘录 ≤200 字）、`law_refs`（法规名称+条号+核心要求）、`suggestion`（可直接替换或删除的修改建议）、`confidence`（`high` / `medium` / `low`）；
   - **待确认事项（若有 `confidence=low`）**：明确列出需用户补充的页面或上下文。

2. **机器可读的 JSON 摘要代码块（`json`）**：
   字段严格遵循：

## 4. 铁律约束（严禁违反）

1. **严禁编造法条**：只可引用真实存在的法律、行政法规与部门规章（优先使用 [`references/laws-and-regulations.md`](references/laws-and-regulations.md) 中已核对的条文）。对地方性实施细则或不确定条号的情形，必须标注"需人工复核地方规定"，并将 `confidence` 设为 `medium` 或 `low`。
2. **证据必须忠于原文**：`evidence` 字段必须摘自招标文件实际文本（控制在 200 字以内），并指明章节/条款号；不得凭空捏造原文未出现的文字。
3. **修改建议必须可执行**：`suggestion` 必须说明"建议将第 X 条改写为……"或"建议删除第 X 条中关于……的限制"，方便招标人/代理机构直接落地修改。
